## Repository Rules

Always inspect the existing code before writing new code.

Reuse existing:
- Components
- Hooks
- Services
- Utilities
- Contexts

Do not create duplicate functionality.

Preserve the existing architecture.

Do not rename or move folders unless explicitly requested.

Do not add new dependencies unless necessary.

Do not modify unrelated files.

Use JavaScript and JSX unless TypeScript is explicitly requested.

Use functional components.

Keep business logic out of reusable UI components.

Keep API communication inside src/services.

Keep pages inside src/pages.

Keep reusable components inside src/components.

When documentation conflicts with existing project code, follow the existing project implementation unless instructed otherwise.

Always explain assumptions.
